# 한게임 틀린그림찾기 · 둘이 함께

**플레이:** https://honkaiduelman.github.io/hangame-difference-coop/

원본 「틀린그림찾기 첩보요원 양성소」를 친구와 2인 협동으로 플레이합니다. 원본 Flash의 그림, 음악, 진행과 사격 훈련을 사용합니다.

## 연결하기

1. **1P가 방 만들기**를 누르고 초대 링크 또는 QR을 친구에게 보냅니다.
2. **2P가 초대를 엽니다.** 자동으로 만들어지는 응답 링크 또는 QR을 1P에게 보냅니다.
3. **1P가 방을 만든 같은 브라우저에서 응답 링크를 엽니다.** 원래 대기방에 자동 적용됩니다. 자동 적용되지 않으면 원래 방의 응답 입력란에 링크를 붙여 넣습니다.
4. 1P·2P가 각자 본인의 요원을 눌러 준비하면 게임이 시작됩니다.

두 사람 모두 게임 탭을 열어 두세요. 게임을 배포한 사람의 PC가 켜져 있을 필요는 없습니다. 해당 방을 만든 1P의 브라우저에서 원본 게임 한 판을 실행하고, 그 게임의 화면·소리를 2P에게 직접 전달합니다. 방장 탭을 닫으면 그 방은 종료됩니다. 카메라·마이크·화면 공유 권한은 사용하지 않습니다.

## 협동 규칙

- **1P는 소년, 2P는 소녀로 고정**합니다. 원본에 이 두 캐릭터의 연필 포인터가 있으므로, 다른 캐릭터 얼굴을 대신 사용하는 방식은 제외했습니다.
- 두 포인터를 실시간으로 표시하고 **연필 끝이 실제 클릭 위치**가 되도록 원본 좌표를 사용합니다.
- 1P의 정답은 원본 빨간 동그라미, 2P의 정답은 파란 동그라미입니다.
- 그림, 찾은 정답, 점수, 하트, 안경과 시간은 공유합니다.
- 하트와 안경은 양쪽 모두 사용할 수 있습니다. 사용 요청 후 **1초 동안 공유 잠금**이 적용됩니다. 원본 화면의 버튼, 별도 버튼, 키보드 모두 같은 규칙을 따릅니다.
- 사격에서는 **탄약과 장전을 각자 관리**합니다. 등장하는 적, 처치, 보상과 시간은 한 판을 공유합니다. 미니게임별 원본 사격·장전 동작과 발사 간격을 유지합니다.
- 일시정지와 재시작은 양쪽에 함께 적용합니다. 연결이 끊기면 원본 게임이 멈춥니다.
- 방장이 다른 탭으로 이동하면 함께 멈추며, 돌아오면 이어집니다. 직접 누른 일시정지는 유지되고, 멈춘 시간은 제한시간에서 차감되지 않습니다.

**조작:** 클릭·터치로 정답 찾기, `1` 하트, `2` 안경. 사격 중 `Space` 또는 장전 버튼. 그림 찾기 중 `Space` 또는 일시정지 버튼. 「함께 다시 시작」은 같은 연결로 두 사람의 준비를 초기화합니다.

**방 채팅:** 두 사람이 연결되면 한글·영어·숫자로 대화할 수 있습니다. `Enter` 또는 전송 버튼으로 보냅니다. 한글 조합을 확정하는 Enter는 메시지를 보내지 않습니다. 넓은 화면에서는 게임 왼쪽, 작은 화면에서는 게임 아래에 표시합니다. 일시정지와 같은 연결의 재시작 중에도 대화 내역은 유지되며, 새 방을 만들면 초기화됩니다. 채팅도 기존 직접 연결을 사용합니다.

**음량:** 게임 아래의 「소리」 슬라이더로 각자 0~100% 범위에서 조절합니다. 0%는 음소거이며, 상대의 음량에는 영향을 주지 않습니다. 준비·소리 켜기·같은 페이지에서 다시 시작을 눌러도 선택한 음량을 유지합니다. 브라우저가 소리 재생을 막으면 「소리 켜기」를 눌러 주세요.

## 서버 없이 연결하는 방식

GitHub Pages는 정적 게임 파일만 제공합니다. 기존 이누야샤 PvP와 같이 **초대·응답 링크를 직접 교환하는 WebRTC 연결**을 사용합니다. 게임 서버, 신호 교환 서버, TURN 중계는 없습니다. QR도 브라우저에서 생성합니다.

초대·응답 링크는 반복되는 연결 정보를 손실 없이 압축한 짧은 HG3 형식을 사용합니다. 기존 HG1·HG2 초대도 읽을 수 있으며, 이전 형식으로 초대한 방에는 같은 형식의 응답을 보냅니다. 연결 방법과 게임 기능은 그대로입니다.

기존 이누야샤 버전의 Cloudflare 공개 STUN(`stun.cloudflare.com:3478`)을 유지했습니다. 연결 가능한 외부 주소를 찾는 용도이며 게임 화면이나 데이터를 중계하지 않습니다. 추가로 관리할 서버나 계정은 필요 없습니다.

일부 공유기·통신사·방화벽 조합에서는 직접 연결이 실패할 수 있습니다. 실패하면 새 링크를 교환하거나 한쪽 회선을 변경해 보세요. 모든 외부 회선 조합을 보장하지는 않습니다. 두 별도 Chrome 프로세스의 직접 연결·실제 원본 게임 검사는 실행하지만, 서로 다른 집의 PC나 모든 실제 모바일 기기는 이 작업 환경에서 시험하지 못했습니다.

## 소스와 검증

`public/`의 정적 파일을 배포합니다. `tools/pages.py`가 검사 전용 SWF를 제외하고 SHA-256 목록을 만듭니다. 원본의 190개 그림 SWF와 좌표 XML 쌍을 보존합니다.

원본 스크립트를 재컴파일하지 않고, 별도로 컴파일한 `flash/coop.as`의 AVM1 태그를 덧붙입니다. `tools/build.py`는 모든 원본 태그가 그대로 남았는지 검사합니다. 개발 환경에서 FFDec와 Java 경로를 지정하고 `python tools/build.py --test`로 검사 전용 프로브도 만들 수 있습니다.

`npm test`로 규칙·링크·실제 두 브라우저 협동 검사를 실행합니다. 브라우저 검사는 설치된 Playwright와 Chrome을 사용하며 `PLAYWRIGHT_MODULE`, `CHROME_PATH`로 경로를 바꿀 수 있습니다. 검사용 프로브의 임의 원본 함수 호출 기능은 배포하지 않습니다.

그림은 공통 화면 배율에서 양쪽 비트맵의 픽셀 위치를 맞춰, 정답이 아닌 글자나 선의 굵기가 달라지는 현상을 줄입니다. 원본 그림과 정답 좌표는 보존합니다. 실제 Heaven 글자를 100%·125%·150% 배율과 다섯 창 너비에서 비교하는 검사는 Python의 Pillow도 사용합니다. 안경·하트는 원본 기능을 실행하되 사진을 가리는 원본 버튼의 단축키 안내는 표시하지 않습니다.
