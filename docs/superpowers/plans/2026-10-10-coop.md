# Hangame Cooperative Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the original Hangame difference game with synchronized two-player cooperation on GitHub Pages.

**Architecture:** Original Flash assets run in bundled Ruffle. An AS2 bridge turns inputs and state into host-authoritative cooperative events over the existing manual WebRTC link transport. Static Pages deployment includes all game assets.

**Tech Stack:** AS2/AVM1, Ruffle, JavaScript ES modules, Python SWF tag tooling, Node tests and Playwright.

**Spec:** `docs/superpowers/specs/2026-10-10-coop-design.md`

## Global Constraints

- All characters unlocked; distinct selections required before start.
- 1P rings red; 2P rings blue; live character cursors.
- Shared life, glasses, pictures, enemies, kills and clocks; 1000 ms resource cooldown.
- Independent minigame bullets.
- No game/signaling/TURN server; retain InuYasha public STUN and manual link/QR exchange.
- New public repository and GitHub Pages; no edits under synced `sources/` or previous repositories.

## Review Focus

- Simultaneous character selection and item use must have one accepted winner.
- Replayed requests and stale stage identifiers cannot spend or score again.
- Keyboard inputs obey the same item locks and shared pause as clicks.
- Slow loading or a disconnected/hidden browser cannot advance a second timeline.
- Enemy identity and rewards remain stable at minigame and normal-stage boundaries.
